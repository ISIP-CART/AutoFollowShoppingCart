# BLE 固件三路传感器集成测试方案

对象：`esp32_at8236_velocity_ble.ino`，中央 URM09-I²C ×1，左右 VL53L1X ×2。
原则：先无电机、再车轮架空、最后仅在空旷场地低速落地；当前传感器为仅日志模式，
不提供前向、侧向或后向防撞保证。

## 1. 准备与记录

- ESP32 Dev Module / ESP32-WROOM-32E，ESP32 Arduino Core 与 Pololu VL53L1X 1.3.1。
- 卷尺或激光测距仪、平整纸箱、黑色布料、可反光平板、秒表；串口 115200。
- I²C 接口和两只 ToF VIN 均为 3.3 V；SDA=21、SCL=22；左/右 XSHUT=25/26。
- 记录固件 commit、板包/库版本、模块物理左右、供电电压、目标材质、真值和电机状态。
- 保存从复位开始的完整串口日志；开启诊断：`!D,1`，查询快照：`!Q`。

建议在正式测试前冻结误差门槛。若暂时没有课程组统一口径，可先用以下工程准入值：
每个固定点连续 30 s 有效率不低于 95%，中位绝对误差不大于 30 mm，P95 绝对误差
不大于 60 mm，健康静态目标下最大有效更新间隔不超过 200 ms。任何模块未达到时，
保留原始数据并停止进入运动验收，不通过放宽固件有效范围来掩盖问题。

## 2. T0：编译与静态检查

1. 编译草图，确认没有缺失 `VL53L1X.h`、ESP32 BLE 或 Wire API 错误。
2. 检查固件中没有 V2 草案的 `m/d/g/a` 解析或发送；现阶段只允许 V1 `s`。
3. 检查 `RANGE_MOTION_GATING_ENABLED=false`；`REQUIRE_RANGE_SENSORS_FOR_MOTION=true`
   仅作为未来门控策略保留。确认 300/400 mm 中央阈值、200/300 mm 角部阈值及
   200 ms 过期时间仍用于日志风险计算。

通过：可重复编译，且上述常量与协议边界一致。

## 3. T1：上电、地址和空闲测距

电机主电源断开，只给 ESP32 与传感器供电：

1. 复位后应依次看到中央 `0x11`、左 `0x2A`、右 `0x2B` 的 `RANGE_BOOT` READY 行。
2. 执行 `!D,1`，观察至少 60 s。`RANGE` 中三路应从 `STALE` 进入 `VALID`；
   ToF `device_status=0`，`age_ms<=200`，日志时间戳持续递增。
3. 执行 `!Q`，确认三路字段齐全，电机目标仍为 0。
4. 连续冷启动 10 次；每次地址分配都应一致，不能出现两只 ToF 同占 `0x29`、总线卡死
   或启动时非零 `$spd`。

通过：10/10 次启动成功，空闲 60 s 内三路均持续更新且车轮无动作。

## 4. T2：单路距离准确度与标签核验

一次只移动一个正对传感器的纸箱，另外两路保持固定：

| 传感器 | 真值点 | 每点记录 |
|---|---|---|
| 左/右 VL53L1X | 100、200、300、500、1000 mm | 各 30 s |
| 中央 URM09 | 300、500、1000 mm | 各 30 s |

核对软件 LEFT/RIGHT 与实物左右一致；计算每点有效率、中位误差、P95 绝对误差、最大
有效更新间隔和最长连续无效段。再用黑布、人体、纸箱边缘和反光板各复测 30 s，异常
质量状态必须显示为 `SIGNAL_INVALID` / `RANGE_INVALID` / `STALE`，不得被替换成最大距离。

通过：纸箱固定点达到本方案准入值；左右标签无交换；无效样本不进入中值和 V1 最小值。

## 5. T3：BLE V1 兼容性

1. Android 连接 `OpenBot: CART_AT8236`，发送 `f`；Notify 应包含
   `fCART_AT8236:s:`，随后在驱动就绪时收到 `r`。
2. Android 自动发送 `s100` 后，每约 100 ms 收到 `s<cm>`；移动三个目标，数值应跟随
   三路“有效且未过期”的最小距离变化，允许厘米取整和 3 点中值造成的小延迟。
3. 发送 `s0` 后停止 V1 距离通知；发送 `s49`、`s1001`、非数字或超长命令均应拒绝，
   且不能改变电机状态。
4. 断开再重连，旧连接的测距周期和缓存字节不能跨 epoch 生效；重新查询 `f` 后恢复。

注意：现有 Android V1 只能显示一个数值，不能表达三路身份和无效原因；完整判定以 ESP32
的 `RANGE`/`!Q` 为准，不把页面最后显示值当作安全状态。

## 6. T4：失效与过期仅记录（车轮架空）

先保持所有传感器有效，持续刷新 `h750` 和低档运动命令：

1. 前进用 `c9,9`；断开 URM09 的 SDA 或电源。最后有效读数超过 200 ms 后日志应显示
   中央 `STALE`，但不得出现 `!ERR,sensor_center_unavailable` 或传感器原因制动。
2. 左转用 `c-5,5`；断开左 ToF，日志应显示左侧失效但命令继续被正常接受；右转与右 ToF 镜像。
3. 分别断开每只模块并执行 `!Q`。运行中已识别的模块应从错误/旧样本进入 `STALE`；
   冷启动时缺失的模块应为 `NOT_PRESENT`。
4. 三路全部断开时，在车轮架空状态依次刷新 `c14,14`、`c-5,5`、`c5,-5`、`c-12,-12`；
   均不得返回任何 `!ERR,sensor_*`，传感器状态不得改变目标轮速或系统运动状态。

通过：断线和过期被准确记录，但没有任何传感器原因的拒绝、制动或目标轮速变化。

## 7. T5：风险锁存仅记录（车轮架空）

1. 刷新 `c9,9`，将纸箱逐步移到中央 300 mm 内；`risk` 应出现 `C`，但不得出现
   `brake_start,reason=sensor_center_near`，运动状态和目标轮速不得因该风险改变。
2. 把纸箱停在 350 mm，`C` 保持；移到 400 mm 以外，连续 3 个有效 URM09 样本后
   `C` 消失。整个过程只改变日志字段。
3. 对左侧 200/300 mm 用 `c-5,5` 重复，确认 `L` 只进入日志；对右侧用 `c5,-5`
   镜像重复并确认 `R` 只进入日志。
4. 障碍存在时发送 `c0,0` 和递增 `!S,<seq>`，二者仍必须可靠停车；急停保持锁存。

通过：触发阈值、解除阈值和连续 3 帧符合预期，且风险锁存只影响诊断输出。

## 8. T6：三路并行、电机干扰与耐久

1. 三路固定目标连续运行至少 10 min，先电机断电，再车轮架空分别执行前进、弧线和原地
   转向；保存两组日志。
2. 对比有效率、误差、最大 age、连续无效段和 I²C/设备状态。线束靠近/远离电机线各做一组，
   一次只改变一个条件。
3. BLE 同时保持 `h750`、`s100` 和 `c` 刷新，确认 Notify 不导致运动超时、BLE 队列溢出
   或 AT8236 `$MSPD` 遥测过期。

通过：两组均无总线冻结、重启、`rx_queue_overflow` 或传感器引起的停车；运动组仍满足
T2 的有效率和 200 ms 更新门槛。若不满足，先处理供电、接地、线束和总线上拉。

## 9. T7：既有安全回归与空旷低速测试

先保持车轮架空，回归与传感器无关的安全机制：

1. `c0,0` 必须进入主动制动；直接正反转换向必须先制动并等待新命令。
2. 停止运动刷新但保留心跳，应由 `motion_timeout` 停车；停止全部写入应由
   `link_timeout` 停车；断开 BLE 也必须停车。
3. 发送递增 `!S,<seq>`，必须进入锁存急停；后续非零 `c` 命令被拒绝，重启后才能恢复。
4. 模拟 AT8236 遥测丢失、反馈反号或超速时，必须进入既有驱动故障保护。

以上通过后，才可在无人员、无货架、无障碍物的空旷平地从 `c9,9` 开始短时低速落地测试，
测试者位于侧后方并可立即物理断电。不得朝障碍物测试“自动停车”，不得因为日志中出现
`risk` 就假定小车会减速。当前版本只验证测距日志不干扰运动控制；启用传感器门控前，
防撞与停车距离测试不属于本版本验收范围。
