# ESP32 + AT8236 四轮速度闭环验证固件

本目录提供一份独立的 USB 验证固件，用于在接入 Android / BLE 前验证：

- AT8236 配置、速度指令和反馈方向是否正确；
- 四轮正反向最低可靠速度；
- 正常停车时由 `$spd:0` 保持板载 PID 制动；
- 每轮、每个物理方向的前馈标定；
- 可选的 ESP32 慢速外层修正；
- 遥测丢失、制动超时和解锁过期时的安全行为。

阶段 A～F 使用四轮悬空模式。完成落地准入检查后，阶段 G～H 使用受限的 `LANDED` 模式验证空载直线，阶段 I～J 使用独立的 `TURN` 模式验证原地转向，阶段 K 使用 `STRAFE` 验证麦轮左右平移，阶段 L 再用 `ARC` 验证跟随控制实际需要的低速弧线。

## 1. 烧录条件

- Arduino IDE 开发板：`ESP32 Dev Module`
- 串口监视器：`115200`，发送行尾选择“新行”
- ESP32 `GPIO17 -> AT8236 RX2`
- ESP32 `GPIO16 <- AT8236 TX2`
- ESP32 与 AT8236 共地
- 电机电源符合 12 V 520 电机要求
- 阶段 A～F 四轮完全悬空，旁边有人可立即切断电机电源

烧录文件：

```text
esp32_at8236_velocity_validation.ino
```

烧录后不要立刻发送运动命令。程序会先：

1. 用 `$pwm:0` 清除可能残留的输出；
2. 写入当前项目参数；
3. 发送 `$read_flash#`；
4. 开启 `$MSPD/$MTEP/$MAll`；
5. 切到 `$spd:0`，由 AT8236 PID 保持停车。

## 2. 当前配置与必须确认的项目

固件当前使用：

```text
mtype=2
mphase=30
mline=11
wdiameter=80 mm
deadzone=1600
MPID=只读取，不自动覆盖
```

项目采购参数已确认减速比 30、磁环 11 线、轮径 80 mm。`mtype` 不能仅按“520 电机”判断，它取决于编码器 A/B 经过实际转接线后是否交叉：

- 电机 A 接驱动板 B、电机 B 接驱动板 A：通常使用 `mtype=1`；
- 电机 A 接驱动板 A、电机 B 接驱动板 B：按供应商资料通常使用 `mtype=2`。

2026-08-31 的 M1 实测已经证明当前接线使用 `mtype=1` 会形成正反馈：`$spd:+50` 时 `$MSPD` 从负向持续增长到约 `-1447 mm/s`，并且 `$spd:0` 无法制动。因此本版在不改变接线的前提下改为 `mtype=2`，同时保持减速比、磁环线数和轮径不变。

固件还增加了两级快速保护：

- 运动中反馈方向连续 120 ms 与目标相反，或速度连续 120 ms 超过安全比例，立即发送 `$pwm:0` 并锁定故障；
- `$spd:0` 制动 600 ms 后任一轮仍超过 `120 mm/s`，立即发送 `$pwm:0`，不再等待电机持续高速运行。

## 3. USB 命令

所有命令以换行结束。

| 命令 | 作用 |
|---|---|
| `!Q` | 查询控制状态、遥测年龄、目标、实际输出和最近序号 |
| `!F` | 让 AT8236 返回掉电保存的配置 |
| `!B` | 查询 AT8236 电源电压 |
| `!A,RAISED` | 确认四轮悬空并解锁 180 秒；同时强制关闭外层修正 |
| `!A,LANDED` | 确认进入有人值守落地模式并解锁 60 秒；每次运动停稳后自动解除解锁 |
| `!A,TURN` | 确认进入有人值守原地转向模式并解锁 60 秒；每次运动停稳后自动解除解锁 |
| `!A,STRAFE` | 确认进入有人值守左右平移模式并解锁 60 秒；每次运动停稳后自动解除解锁 |
| `!A,ARC` | 确认进入有人值守低速弧线模式并解锁 60 秒；每次运动停稳后自动解除解锁 |
| `!T,seq,motor,speed,duration` | 单轮原始 `$spd` 阶跃，不使用轮间补偿 |
| `!D,seq,left,right,duration` | 车体左右侧速度测试，使用方向补偿；正值表示车体前进 |
| `!Y,seq,right,duration` | 专用左右平移测试；`right>0` 预期向车体右侧，`right<0` 预期向左侧 |
| `!G,motor,fg,rg,fb,rb` | 临时设置某轮前进/后退增益与偏置，重启失效 |
| `!L,0` / `!L,1` | 关闭/开启受限慢速外层修正，默认关闭 |
| `!S,seq` | 使用 `$spd:0` 制动、确认停稳并解除解锁 |
| `!R,seq` | 仅在四轮确认静止后用 `$pwm:0` 释放输出并解除解锁 |

范围：

- `motor=1..4`
- `speed/left/right=-250..250 mm/s`，不能四轮全为 0
- `duration=800..5000 ms`
- `seq` 必须为递增正整数
- `fg/rg=500..1500`，单位为千分比；`1000` 表示 1.000
- `fb/rb=0..100 mm/s`

`LANDED` 模式有额外硬限制：

- 只接受 `!D`，拒绝单轮 `!T`；
- `left` 必须等于 `right`，只允许直线，不允许转向；
- 速度绝对值不超过 `100 mm/s`；
- 单次时间不超过 `5000 ms`，在 `100 mm/s` 上限下理论行程不超过约 0.5 米；
- 禁止启用外层修正和在线修改轮子补偿；
- 每次运动停稳后自动回到 `SAFE_HOLD`，下一次必须重新发送 `!A,LANDED`。

`TURN` 模式与直行模式相互隔离，并有以下额外硬限制：

- 只接受 `!D`，拒绝单轮 `!T`；
- `left` 必须等于 `-right`，只允许左右轮组等幅反转的原地转向，不允许弧线行驶；
- 左右侧速度绝对值必须在 `60～100 mm/s`；低于 60 的原地转向请求会被拒绝；
- 单次时间必须在 `1000～2000 ms`；
- 禁止启用外层修正和在线修改轮子补偿；
- 每次运动停稳后自动回到 `SAFE_HOLD`，下一次必须重新发送 `!A,TURN`。

`TURN` 只是底盘调试授权，不是 Android 自主运行模式。转向验证通过前，不把该限制扩大到一般差速指令。

`STRAFE` 模式与直行、转向模式相互隔离，并有以下硬限制：

- 只接受专用 `!Y`，拒绝 `!D` 和单轮 `!T`；
- 横移速度绝对值必须在 `80～100 mm/s`；阶段 K 已证明60档不够可靠；
- 单次时间必须在 `1000～2000 ms`；
- 禁止启用外层修正和在线修改轮子补偿；
- 每次运动停稳后自动回到 `SAFE_HOLD`，下一次必须重新发送 `!A,STRAFE`。

正向 `!Y` 的预期物理轮向为 `M1后退、M2前进、M3前进、M4后退`；结合当前接线映射，AT8236 目标符号应全部为负。负向 `!Y` 应全部反向，AT8236 目标符号应全部为正。

`ARC` 模式只接受 `!D`，并限制为：

- `left/right` 必须非零、同号，只允许前进弧线或后退弧线；
- 外侧速度绝对值必须为 `100 mm/s`，内侧速度只允许 `40～80 mm/s`；
- 两侧速度差必须在 `20～60 mm/s`，排除直线、单侧停转和原地旋转；
- 单次时间必须在 `1000～4000 ms`；
- 禁止外层修正和在线轮间标定，每次停稳后自动回到 `SAFE_HOLD`。

`!G` 的 forward/reverse 指车体物理方向，不是 AT8236 命令的正负号。当前物理前进映射为：

```text
M1 +, M2 -, M3 -, M4 +
```

## 4. 分阶段验证

### 阶段 A：只核验配置和静止状态

1. 四轮悬空并接通电源，烧录后重新上电。
2. 等待看到：

   ```text
   VEL,...event=driver_config_sent...
   VEL,...event=ready,mode=spd_zero_pid_hold
   ```

3. 连续观察 5 秒，`mspd` 四项应接近 0，状态应为 `SAFE_HOLD`。
4. 发送 `!F`，保存驱动板返回内容，核对 `mtype/mphase/mline/wdiameter/deadzone/MPID`。
5. 发送 `!B`，记录空载电压。
6. 用手轻推轮子。`$spd:0` 下应能感到 PID 保持；不要长时间强行拧动。

若没有 `ready`、遥测中断或静止时某轮持续非零，停止测试并检查串口、编码器和 `mtype`。

### 阶段 B：验证反馈符号与速度语义

1. 发送 `!A,RAISED`。
2. 先用最低风险的短脉冲验证 M1 相位：

   ```text
   !T,1,1,20,800
   ```

3. 正常结果必须是 `$MSPD` 与 `$spd` 同号，且不会持续加速。若出现 `feedback_sign_mismatch_m1`、`overspeed_m1` 或 `pid_brake_failed_m1`，固件会进入 `FAULT_DISABLED`；此时必须断电复位，不能继续发序号 2。
4. 序号 1 正常结束后，等待 `event=brake_settled`，再额外等待 1 秒冷却时间；发送 `!Q`，确认 `state=ARMED_IDLE,armed=1` 后再执行：

   ```text
   !T,2,1,-20,800
   !T,3,1,50,1500
   !T,4,1,-50,1500
   !T,5,1,100,1500
   !T,6,1,-100,1500
   ```

5. 每一条都重复上述“等待 `brake_settled`、再等 1 秒、用 `!Q` 确认 `ARMED_IDLE`”的步骤。
6. 检查速度是否大致随 20 -> 50 -> 100 增大。如果 `$spd=50` 时 `$MSPD` 仍瞬间达到数百且无法收敛，应停止速度闭环测试，继续核查 AT8236 的 MPID 或驱动板固件。

### 阶段 C：四轮原始速度重复性

保持外层修正关闭。每个轮子、每个方向执行 5 次 `100 mm/s、2000 ms`：

```text
!T,10,1,100,2000
!T,11,1,-100,2000
...
!T,48,4,100,2000
!T,49,4,-100,2000
```

每次记录：

- 起步后 600..1600 ms 的 `$MSPD` 中位数；
- `brake_start` 到 `brake_settled` 的时间；
- `delta_mall`；
- 是否发生 `feedback_sign_mismatch`、`overspeed`、`pid_brake_failed`、`telemetry_timeout` 或 `brake_timeout`。

单方向 5 次中至少 4 次应可靠起转；同轮同方向稳态速度离散建议先控制在 ±15% 内。做不到时先处理硬件、编码器或 AT8236 内环，不进入轮间补偿。

### 阶段 D：设置方向相关前馈

以四轮同一物理方向的稳态 `$MSPD` 中位数为基准，先只调整增益，不加 bias：

```text
新增益 = 当前增益 × 目标速度 / 该轮实测速度
```

增益首次只允许限制在 `800..1250`，避免一次改动过大。例如临时把 M2 前进增益设为 1.15、其他保持 1.00：

```text
!G,2,1150,1000,0,0
```

然后执行悬空车体直行：

```text
!D,60,100,100,2500
!D,61,-100,-100,2500
```

如果一个方向改善、另一个方向变差，应分别调整 `fg/rg`，不要使用一个双向统一 trim。

### 阶段 E：验证慢速外层修正

只有阶段 B 已确认 `$MSPD` 与 `$spd` 同号、阶段 C 没有反馈异常后才能执行：

```text
!L,1
!D,70,100,100,3000
```

检查：

- `correction` 每 200 ms 最多变化 2 mm/s；
- 单轮累计修正不超过 ±30 mm/s；
- `driver` 不反向、不超过 ±250 mm/s；
- 任一轮反馈方向不符时立即进入 `brake_start`；
- 外层开启后的四轮稳态差异应比关闭时更小，且不出现周期性振荡。

若出现振荡，立即发送递增序号的 `!S,seq`，保留外层关闭。首版课程原型允许只使用已验证的方向前馈，不强制启用外层修正。

### 阶段 F：停车与故障保护

1. 运动过程中发送 `!S,seq`，应先看到 `brake_start,mode=spd_zero_pid_hold`，随后看到 `brake_settled`。
2. 正常停车过程中不应出现 `pwm_zero`。
3. 停稳后发送 `!R,seq`，才应出现 `output_released,mode=pwm_zero`。
4. 运动时拔掉 AT8236 TX 到 ESP32 RX 的遥测线，固件应进入 `FAULT_DISABLED` 并发送 `$pwm:0`。完成后必须断电复位，不允许继续运动。
5. `$spd:0` 后 600 ms 任一轮仍超过 `120 mm/s`，固件应报 `pid_brake_failed_mN` 并关闭 PWM 输出；其他未能在 2 秒内停稳的情况应报 `brake_timeout`。

故障注入只允许四轮悬空执行。

### 阶段 G：空载落地直线测试

四轮同时悬空测试已经得到前进 `delta_mall=1313,-1313,-1313,1313`、后退 `-1313,1313,1313,-1313`，且均正常停稳，因此不需要修改四轮增益或启用外层修正。落地测试按以下步骤执行。

#### 场地与人员

1. 卸下购物筐内载荷，选择平整、干燥、至少前后各 1 米无障碍的地面。
2. 检查四个麦轮安装方向、轮毂紧固和轮子是否自由转动。
3. USB 线留出余量，操作人员站在小车侧后方，禁止站在车头或车尾正前方。
4. 另一人负责电机电源开关；任何异常优先直接切断电机电源。
5. 在车体中心线和地面起点贴胶带，便于观察偏航和停车距离。

#### 上电检查

等待 `SAFE_HOLD` 后发送：

```text
!Q
!B
```

只有满足以下条件才继续：

- `state=SAFE_HOLD,armed=0,arm_mode=NONE`；
- 四轮 `$MSPD` 均在 `±60 mm/s` 内，`MAll` 没有持续单向累积；
- 电池电压正常，现场可以随时断电。

#### 逐级运动

每一级都必须等待 `event=brake_settled`，确认状态回到 `SAFE_HOLD`，检查轮子、方向和场地后才进入下一级：

```text
!A,LANDED
!D,100,40,40,800

!A,LANDED
!D,110,-40,-40,800

!A,LANDED
!D,120,60,60,1000

!A,LANDED
!D,130,-60,-60,1000

!A,LANDED
!D,140,80,80,1200

!A,LANDED
!D,150,-80,-80,1200

!A,LANDED
!D,160,100,100,1500

!A,LANDED
!D,170,-100,-100,1500
```

序号故意留有间隔。如果运动中需要串口急停，例如正在执行序号 140，可发送：

```text
!S,141
```

但串口急停不能替代现场断电开关。

#### 每一级记录与停止条件

记录运动方向、四轮稳态 `$MSPD`、`delta_mall`、肉眼偏航方向和从 `brake_start` 到完全静止的距离。出现以下任一情况立即停止后续测试：

- 某轮持续不转、打滑、离地或发出明显异常声音；
- 车体明显偏转，不能保持短距离直线；
- 同次测试四轮 `delta_mall` 绝对值相差超过约 10%；
- 出现 `feedback_sign_mismatch`、`overspeed`、`pid_brake_failed`、`telemetry_timeout`、`brake_timeout` 或 `FAULT_DISABLED`；
- 停车后车体继续明显移动，或电机、驱动板、接线出现异常发热。

全部八次通过后，只能说明“空载、低速、短距离落地直线”通过；还不能直接视为载物、转向或 Android 无人值守测试通过。

### 阶段 H：空载稍长距离直线测试

短距离落地结果已经确认：

- `40 mm/s、800 ms` 前进四轮脉冲绝对值为 `163,156,154,155`，后退为 `142,143,141,141`；
- `100 mm/s、1500 ms` 前进为 `770,778,778,765`，后退为 `778,788,790,775`；
- 100 档前后轮间差均小于约 2%，停车约 0.5 秒，没有触发任何安全故障。

因此长距离阶段不提高速度，只把 `100 mm/s` 的持续时间逐级延长到 2、3、5 秒。准备至少前后各 1.5 米的平整空场，在起点、20 cm、30 cm 和 50 cm 位置贴胶带。

每条命令结束后都要等待 `brake_settled` 和自动回到 `SAFE_HOLD`，然后重新解锁：

```text
!A,LANDED
!D,200,100,100,2000

!A,LANDED
!D,210,-100,-100,2000

!A,LANDED
!D,220,100,100,3000

!A,LANDED
!D,230,-100,-100,3000

!A,LANDED
!D,240,100,100,5000

!A,LANDED
!D,250,-100,-100,5000
```

若运动中需要串口急停，使用对应测试序号之后的一个序号，例如执行 `240` 时发送：

```text
!S,241
```

每一级记录：

- 四轮 `delta_mall` 绝对值及最大/最小差异；
- 车体中心相对地面中心线的横向偏移和车头偏角；
- `brake_start` 到 `brake_settled` 的时间与实际停车滑行距离；
- 测试前后的电池电压、驱动板和电机温度体感。

建议准入标准：

- 同次四轮 `delta_mall` 绝对值最大差异不超过 5%；
- 50 cm 测试横向偏移不超过约 5 cm，且偏差不是持续增大的弧线；
- 制动在 800 ms 内完成，额外滑行不超过约 10 cm；
- 没有单轮停转、打滑、异常声音、异常发热或任何 `FAULT_DISABLED` 类故障。

如果只有一次轻微偏移，先重复同方向两次再判断；只有偏移方向和幅度可重复，才进入方向相关轮间补偿，不根据单次结果修改增益。

### 阶段 I：空载低速原地转向测试

本次 2、3、5 秒直行结果已达到转向准入条件：六次测试四轮累计量离散约为 `1.2%～3.1%`，5 秒前进约 `1.3%`、后退约 `2.2%`，制动约 `0.46～0.57 s`，没有安全故障。因此本阶段保留现有中性轮间补偿，并只开放独立、受限的 `TURN` 模式。下面的 40～60 mm/s 命令是阶段 I 已完成测试的历史记录；最新版固件已经不再接受低于 `60 mm/s` 的落地转向命令。

准备工作：

1. 使用最新版固件重新烧录 ESP32。
2. 清出以车体中心为圆心、直径至少 2 米的平整区域，移除串口线可能缠绕到的障碍。
3. 在车体几何中心下方的地面贴十字标记，在车头贴一条方向箭头；建议从正上方录像。
4. 保持空载、相同地面和当前电池状态。操作员站在旋转范围之外，并可立即发送急停或切断电机电源。
5. 发送 `!Q`，确认 `SAFE_HOLD`、`armed=0`、`arm_mode=NONE` 且四轮静止。

按以下顺序逐级测试。每条命令后都必须等待 `brake_settled` 和自动返回 `SAFE_HOLD`，再等待至少 1 秒冷却时间，测量并记录后才重新解锁：

!A,TURN

按常规差速定义，`left>0,right<0` 应向右原地转，反向组合应向左原地转。若实车方向相反，先记录实际方向，不立即交换电机线或修改映射。第一条命令的预期 AT8236 目标符号为 `M1+,M2+,M3-,M4-`，反向命令应为 `M1-,M2-,M3+,M4+`。

每一级记录：

- 实际转向方向、转过的角度以及车体中心相对地面十字的平移量；
- 四轮是否同时起转，是否有单轮拖行、跳动或麦轮横向异常滑动；
- 四轮 `delta_mall` 的符号和绝对值；
- `brake_start` 到 `brake_settled` 的时间及停车后的额外转角；
- 两个方向完成同档测试后，电机、驱动板和接线温度体感。

建议进入下一阶段的标准：

- 两个方向都与预期一致，四轮编码器符号符合上述组合；
- `60 mm/s、2000 ms` 时四轮 `delta_mall` 绝对值最大差异不超过约 10%；
- 左右两个方向的转角绝对值差异不超过约 15%；
- 车体中心平移不超过约 5 cm，且不存在稳定复现的单一漂移方向；
- 制动在 800 ms 内完成，没有单轮停转、打滑、异常声音、异常发热或任何故障保护。

若 `40 mm/s` 不能可靠克服原地转向静摩擦，但 `60 mm/s` 能平顺起转，可记录为转向最低可靠速度差异，暂不加轮子偏置。若出现明显平移、某一轮持续停转或左右转角严重不对称，应停止后续测试并提交完整日志和俯视现象，不直接提高速度或修改 PID。

阶段 I 实测结果：

### 阶段 J：确定可靠原地转向工作档

最新版固件作了三项收敛：`TURN` 只允许 `60～100 mm/s`、单次只允许 `1000～2000 ms`，并把停稳判断阈值从 `60 mm/s` 降至 `30 mm/s`。后者仍容许日志中常见的 `±19.04 mm/s` 静止量化噪声，但不会再把仍有 `38～57 mm/s` 的轮子判为停稳。AT8236 PID、四轮增益和方向映射均保持不变。

重新烧录后，先执行两次 60 档基线，再逐级测试80和100档。每条命令后都要等待 `brake_settled`、`SAFE_HOLD` 和至少1秒冷却时间：

```text

!D,400,60,-60,1500

!A,TURN
!D,410,-60,60,1500

!A,TURN
!D,420,80,-80,1200

!A,TURN
!D,430,-80,80,1200

!A,TURN
!D,440,80,-80,2000

!A,TURN
!D,450,-80,80,2000

!A,TURN
!D,460,100,-100,1200

!A,TURN
!D,470,-100,100,1200

!A,TURN
!D,480,100,-100,2000

!A,TURN
!D,490,-100,100,2000
```

每一档必须先完成两个方向，才能进入下一档。若80档已能获得清晰、平顺且可控的转向，100档仍用于短时验证，但后续默认转向档可优先选80而不是追求更快。

每次记录车体转角、中心平移、四轮 `delta_mall`、制动时间和额外转角。建议通过标准：

- 四轮反馈符号与目标一致，且全部在运动开始后约0.8秒内可靠起转；
- 同一测试四轮 `delta_mall` 绝对值差异不超过约10%；
- 同档左右转角绝对值差异不超过约15%；
- 车体中心平移不超过约5 cm；
- `brake_settled` 不超过约0.9秒，车体没有明显的停车后继续旋转；
- 没有单轮停转、剧烈跳动、异常声音、异常发热或任何故障保护。

若80档已经通过而100档出现明显冲击、打滑或中心漂移，应停止在80档，不需要追求100档。阶段 J 通过后先进行独立的左右平移验证；原地转向和平移特性都确认前，仍不开放一般差速组合或弧线模式。

阶段 J 实测结果显示：

- `80 mm/s、2000 ms` 正转为 `781,718,-802,-761`，反转为 `-781,-714,797,760`，成对相加后每轮残差仅为 `0,4,-5,-1`；
- `100 mm/s、2000 ms` 正转为 `1000,933,-1016,-972`，反转为 `-991,-919,1014,986`，成对残差为 `9,14,-2,14`；
- 全部10次运动反馈方向正确，制动约 `0.51～0.68 s`，没有故障保护。

因此“先右转再左转后角度基本回正”与编码器数据一致。M2在长时转向中通常比M3少约6%～10%，但这种差异在反向时也近似镜像，现阶段不能据此写入全局轮间补偿，否则可能破坏已经通过的直线性能。角度回正后微微左移，更可能来自编码器无法观测的轮地作用：麦轮滚子变形与侧滑、四轮载荷不均、轮子左右旋型号或安装位置、地面坡度/纹理，以及USB串口线在旋转后的拖拽。下一阶段用专用横移测试量化这些因素。

### 阶段 K：空载受限左右平移测试

这一阶段用于验证麦轮安装与轮地侧向作用，也用于解释转向后的微小横移；它是底盘诊断/选做能力，不改变首版 Android 跟随仍以低速前进、后退和差速转向为主的控制路线。

下面包含60档的命令是阶段 K 已完成测试的历史记录。最新版固件已把横移最低速度收敛到 `80 mm/s`，重新烧录后低于80的 `!Y` 会返回 `!ERR,Y strafe_limit`。

准备工作：

1. 烧录最新版固件，清出车体左右各至少1.5米的平整空间。
2. 在车体中心下方贴十字，并画车头方向线。记录横向位移、前后漂移和车头偏角。
3. 核对四只麦轮的左右旋型号与安装位置，确保不是四只同型轮，并确认四轮都能完整接地。
4. 将USB线从车体中心上方悬挂，或在两侧保留对称松弛量，不能让线缆持续拉向左侧。
5. 发送 `!Q`，确认 `SAFE_HOLD`、`armed=0`、`arm_mode=NONE` 且四轮静止。

先执行60档方向确认，再逐级测试80和100档。`!Y` 的正值预期向右、负值预期向左：

```text

!A,STRAFE
!Y,510,-60,1000

!A,STRAFE
!Y,520,80,1200

!A,STRAFE
!Y,530,-80,1200

!A,STRAFE
!Y,540,80,2000

!A,STRAFE
!Y,550,-80,2000

!A,STRAFE
!Y,560,100,1200

!A,STRAFE
!Y,570,-100,1200

!A,STRAFE
!Y,580,100,2000

!A,STRAFE
!Y,590,-100,2000
```

每条命令后等待 `brake_settled`、`SAFE_HOLD` 和至少1秒冷却。执行正向后先记录单程位置，再执行反向并记录成对返回残差；不要在两条命令之间手动挪动车体。

第一条正向命令的 `desired/driver` 预期为四项全负，反向命令预期为四项全正。若实车实际向左而不是向右，或主要表现为旋转/前后移动，应立即停止该档后续测试，保存日志并拍摄俯视轮子运动，不要自行换线。

建议通过标准：

- 左右两个方向都以横向移动为主，方向互为相反；
- 同档左右单程距离绝对值差异不超过约15%；
- 一对右移/左移结束后的横向残差不超过单程距离的约15%；
- 单程前后漂移不超过约5 cm，车头偏角不超过约5度；
- 同次四轮 `delta_mall` 绝对值差异不超过约15%；
- 制动不超过约0.9秒，没有单轮停转、剧烈跳动、异常声音、异常发热或任何故障保护。

如果60档只轻微动作但80档平顺，可把80作为横移最低可靠档。如果80档已经满足展示需要，100档只用于确认余量；一旦100档出现明显滚子冲击、偏航或漂移，就停止在80档。平移结果出来前不加入转向侧移补偿。

阶段 K 实测结果：

- 60档右移/左移累计量分别为 `-259,-235,-204,-234` 和 `234,165,144,203`，往返后残留约 `25～70` 个脉冲，制动约 `1.08～1.43 s`，说明仍处于横向静摩擦门槛附近；
- 80档2秒右移/左移为 `-754,-783,-765,-750` 和 `763,781,764,744`，成对残差仅 `9,-2,-1,-6`，轮间离散约5%；
- 100档2秒右移/左移为 `-1002,-987,-962,-988` 和 `1003,992,954,986`，成对残差仅 `1,5,-8,-2`，轮间离散约5%；
- 80/100档制动约 `0.70～0.91 s`，没有运动安全故障。日志里的两次 `!ERR,A format` 和一次 `!ERR,unsupported` 是未被执行的输入格式错误，不影响运动结论。

因此不修改 PID 或轮间增益，把80作为横移最低可靠档即可。100档保留用于验证余量，但默认优先使用80。

!D,630,-80,-100,1500

每条命令后必须等待 `brake_settled`、`SAFE_HOLD` 和至少1秒冷却。前四条是80/100柔和弧线的前进/后退镜像；中间四条是60/100中等弧线；最后两条只在前面全部平顺时测试较长的前进柔和弧线。

按常规差速关系，前进时 `left=100,right=80` 应向右弯，`left=80,right=100` 应向左弯。后退时只要求两组轨迹互为镜像，不要在首次测试前假定车尾的视觉方向。

每次记录：

- 实际前进/后退方向、弯曲方向、终点车头偏角；
- 起点到终点的大致弧线是否连续，有无先直行后突然转动；
- 四轮 `delta_mall`，以及左右两侧累计量是否体现外侧快、内侧慢；
- 制动时间和停车后额外滑行/转角；
- 是否出现麦轮横向滑移、单轮跳动、异常声音或发热。

建议通过标准：

- 所有命令都形成连续弧线，不出现原地旋转、明显横移或单侧停转；
- 相同档位的左右镜像弧线，转角绝对值差异不超过约15%；
- `100/80` 应比 `100/60` 更平缓，轨迹变化方向正确；
- 四轮反馈符号正确，同侧前后轮累计量差异不超过约10%；
- 制动不超过约0.9秒，没有故障保护或明显机械异常。

如果 `100/80` 已经平顺，而 `100/60` 出现内侧轮拖动或车体跳动，后续跟随默认只使用80/100的柔和弧线。阶段 L 已确认组合运动稳定；由于本次目测转角偏小，先完成阶段 M 的转角标定，再把“直线 + 柔和弧线 + hard STOP”接入 Android 手动遥控链路。横移不作为首版自主跟随必需动作。

阶段 L 实测结果表明差速执行正确，但测试转角偏小：

- `100/80、1500 ms` 四组左右侧累计比约为 `1.24～1.27`，与命令目标 `1.25` 一致；
- `100/60、1500 ms` 四组左右侧累计比约为 `1.63～1.72`，与命令目标 `1.67` 接近；
- `100/80、2500 ms` 两组左右平均脉冲差约为 `250～274`；
- 全部命令制动约 `0.50～0.58 s`，没有安全故障。

因此目测不足5度不是 PID 未执行差速，而是原阶段的差速量和持续时间过于保守，且麦轮侧滑会损失部分理论转角。不要提高外侧速度或修改 PID；下一阶段保持外侧 `100 mm/s`，先延长持续时间，再按门槛测试内侧 `40 mm/s`。

在地面以初始车头方向画出 `5°、10°、15°、20°` 参考线，建议俯视录像。每次记录实际车头角度，以及新版 `brake_settled` 后附加的：

```text
arc_left_abs_avg=...
arc_right_abs_avg=...
arc_abs_diff=...
```

#### M1：保持100/60，只延长到2.5秒

每组可以计算一次角度换算系数：

```text
每脉冲差角度 = 实测车头角度 ÷ arc_abs_diff
```

左右方向各重复两次。如果换算系数接近，后续可以用编码器脉冲差估算开环转角；如果不同地面或载荷下差异明显，则说明侧滑占主导，不应依靠固定时间获得精确角度，Android 跟随应继续采用视觉反馈的小步连续修正，或后续再引入手机陀螺仪闭环。

阶段 M 实际执行到 M2 后，运动稳定性与编码器镜像一致性已经通过：

- `100/60、2500 ms` 四组 `arc_abs_diff` 为 `522,514,529,495`，正反与左右镜像一致；
- `100/60、3500 ms` 左右两组为 `753,706`，差异约6%；
- 同侧前后轮累计量差基本在10%内；
- 制动约 `0.60～0.66 s`，没有输入错误或运动安全故障。

日志本身不包含人工测得的车头角度，是否达到目标角度仍以地面角度线或俯视视频为准。若实车转角已经满足演示需要，后续把 `100/60、2500 ms` 作为中等弧线基准，`100/60、3500 ms` 只用于需要更大转角的低速展示，无需修改 PID、轮间补偿或继续测试100/40；若仍不足，再返回 M3，而不是直接提高外侧速度。

### 阶段 N：分段组合路线与渐进载物测试

这一阶段验证“已经分别通过的动作放在同一场地连续使用时是否仍可重复”，并首次检查载物后起步、转向和制动。仍然采用每段停稳、人工确认、重新解锁的方式，不开放无人值守连续路线。

#### N0：空载分段组合路线

准备至少 `3 m × 3 m` 空场，从同一个起点依次执行，段间不要手动挪动车体。每段等待 `brake_settled`、`SAFE_HOLD` 和至少1秒冷却，并在地面标记停车姿态：

```text
!A,LANDED
!D,900,100,100,3000

!A,ARC
!D,910,100,60,2500

!A,LANDED
!D,920,100,100,2000

!A,ARC
!D,930,60,100,2500
```

这条路线依次为“直行—右弧线—直行—左弧线”。记录每段车头角度、中心位置、制动距离和 `delta_mall/arc_abs_diff`。完整路线重复两次，两次最终姿态应大致一致；若同一段偏差方向可重复，再分析该动作，不对整条路线一次性加补偿。

#### N1：2 kg居中载物

将2 kg配重固定在载物平台中心、尽量低的位置，禁止使用人员或易滚动物品作为配重。先发送 `!B` 记录电池电压，再执行：

```text
!A,LANDED
!D,1000,100,100,3000

!A,LANDED
!D,1010,-100,-100,3000

!A,TURN
!D,1020,80,-80,1500

!A,TURN
!D,1030,-80,80,1500

!A,ARC
!D,1040,100,60,2500

!A,ARC
!D,1050,60,100,2500
```

最后单独验证操作员主动停车。发送运动命令后约2秒发送下一条 `!S`：

```text
!A,LANDED
!D,1060,100,100,5000
!S,1061
```

必须在车辆仍处于直行时发送 `!S,1061`，记录从 `brake_start,reason=manual_stop` 到停稳的时间和实际制动距离。完成后再次发送 `!B`，触摸检查电机、驱动板和接线是否异常发热。

#### N2：5 kg居中载物

只有2 kg全部通过后才能增加到5 kg。先不重复全部动作，只执行关键子集：

```text
!A,LANDED
!D,1100,100,100,3000

!A,LANDED
!D,1110,-100,-100,3000

!A,TURN
!D,1120,80,-80,1500

!A,TURN
!D,1130,-80,80,1500

!A,ARC
!D,1140,100,60,2500

!A,ARC
!D,1150,60,100,2500
```

5 kg主动停车：

```text
!A,LANDED
!D,1160,100,100,5000
!S,1161
```

建议准入标准：

- 载物后四轮都能可靠起转，没有单轮拖行或持续打滑；
- 直行同次四轮 `delta_mall` 绝对值差异不超过约8%；
- 80档左右原地转角、100/60左右弧线角度差异不超过约15%；
- 正常到时停车和操作员主动停车均在约1秒内完成，实际额外滑行不超过约10 cm；
- 电池电压无异常下降，电机、驱动板、端子和接线没有异常发热；
- 没有 `telemetry_timeout`、`feedback_sign_mismatch`、`overspeed`、`pid_brake_failed`、`brake_timeout` 或其他故障。

如果2 kg通过但5 kg出现起步不齐、制动距离明显增长或发热，应把首版演示载荷暂定为2 kg，不通过提高速度、PID或死区强行解决。阶段 N 通过后，再进入 Android 手动遥控链路接入和通信心跳停车测试。

## 5. 落地准入与 Android 集成

满足以下条件后才能以最低速度落地：

- 四轮正反向反馈符号全部明确；
- 每轮每方向 5 次测试至少 4 次可靠起转；
- 没有遥测超时、反馈反号或制动超时；
- 前进和后退的左右侧稳态差异均已降到可接受范围；
- `$spd:0` 能可靠制动，`$pwm:0` 只用于停稳后的释放或反馈故障；
- 电池带载电压没有明显跌落。

Android 集成时保留现有 OpenBot `c<left>,<right>` 接口，只把左右归一化量换算为真实 mm/s，再复用本固件的：

```text
左右速度 -> 四轮物理方向映射
          -> 每轮/每方向前馈
          -> 可选慢速外层修正
          -> $spd 四轮目标
          -> $MSPD 停稳与故障判断
```

不要把本验证固件直接当作无监督落地固件；它不包含 BLE、Android 心跳和障碍停车接口。
