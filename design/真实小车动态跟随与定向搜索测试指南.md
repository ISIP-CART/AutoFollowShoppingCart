# 真实小车动态跟随与定向搜索测试指南

更新日期：2026-09-03。对象：OpenBot「真实小车跟随」页面。

本指南包含 2026-09-03 的连续远离身份维持修复。最终构建数量和哈希见开发日志第 33 节，
**本轮尚未安装和进行真车验收**。
APK：`dev/OpenBot/android/robot/build/outputs/apk/debug/robot-debug.apk`。
优先按 [连续远离身份维持复测指南](连续远离身份维持复测指南.md)完成单人远离与干扰者复测。

## 1. 本次增加了什么

- 接入动态 Gallery、近期记忆和黄框片段延后学习。首次仍自动采集 15 帧，由用户确认一次。
- 可靠单人连续观测且新鲜独立分数满足 0.80/Anchor 0.70/margin 0.08 时允许低档维持；
  不满足条件立即停车，保留可靠关联继续验证或学习，不使用旧的 1 秒弱身份续行。
- 目标长时间离开后保留 Start 和记忆，静止等待；严格验证通过后自动恢复，不要求重拍。
- 自动前进开放低、中、高三档 `c14/c18/c21`；每次停车后重新起步先用低档。
- 可选可信侧边离屏后的定向旋转。每次进入页面默认关闭，必须在 Start 前明确开启。

这是受控实验版本，没有超声波、红外或 ToF，不能视为可靠避障系统。

## 2. 开始前

1. 使用当前速度闭环固件 `firmware/esp32_at8236_velocity_ble/esp32_at8236_velocity_ble.ino`。
2. 手机固定在车体上，不能由旁人单独转手机来代替实车转角。独立测角测试除外。
3. 准备空旷场地、空载小车和一名能立即物理断电的同学，手和衣物远离车轮。
4. 先确认手动停车、松手停车、断连停车和软件急停有效。软件急停不能替代物理断电。
5. 首轮四轮悬空，主动搜索关闭。不要同时开始高速跟随和旋转搜索。

旧 `esp32_at8236_openbot_ble` 的 trim、kick 和固定等待说明仅供历史参考。本轮不修改固件。
现有 `c<left>,<right>` 已表达方向和速度，横移仍未接入，BLE 格式不变。

## 3. 页面设置

切换到「自动实验」，Start 关闭时设置：

| 控件 | 默认值 | 首轮建议 |
|---|---|---|
| Gallery / 近期记忆 | 动态 / 开启 | 保持，之后与固定对照 |
| 自动最高档 | 21 | 主动选 14，通过后再 18、21 |
| 主动定向搜索 | 每次进入页面关闭 | 前两阶段始终关闭 |
| 旋转档位 | 首次 5 | 先 5，不直接升到 21 |
| 最大角度 / 总时限 | 首次 90° / 5 秒 | 包含停车等待和身份验证 |
| 转弯强度 | 保留以前值，首次 100% | 检查取值，建议从 100% 开始 |

档位上限、Gallery、近期记忆和搜索数值会保存；搜索开关不跨页面保存。
Start 后这些设置锁定，只有原有转弯强度仍可实时调整。设置区可滚动。
完成 BLE 握手后长按解锁，打开 Start，再采集并确认目标。

## 4. 悬空检查身份与停车

全程关闭主动搜索，上限选 14，建议打开「记录日志」。

1. 采集、确认和首次 3 秒倒计时期间，实际输出必须始终为 `c0,0`。
2. 目标远离到有效跟随距离，稳定后先出现 `c14,14` 或低档正向差速。
3. 目标缓慢转身、蹲下、改变姿态。「连续跟踪 · 低档」可在其他门通过后输出低档；
   「姿态适应」「身份验证」必须输出零。维持证据不是强身份授权，不得升档。
4. 短暂离开再返回，先停车验证，通过后低档恢复，不重复首次倒计时。
5. 目标离开超过 2 秒，应静止等待，Start 保持开启，Anchor 和已接纳 Adaptive 不清空。
6. 长时间后返回，观察全局验证进度：需 5 次新鲜证据且跨度至少 1.2 秒，未通过不得运动。
7. 相似衣着路人进入时，已知干扰者不得接管，存在多人歧义时必须停车。
8. 分别检查关闭 Start、切换手动、退出页面、断开 BLE、急停后轮子是否停转。

绿框只说明身份状态，不等于允许运动。查看「实际输出」及停车原因。
相对高度比例不是米制距离，本轮没有调整跟随距离。

## 5. 空旷场地三档跟随

上一阶段全部通过后才落地，仍关闭主动搜索。

1. 自动最高档依次选 `14 → 18 → 21`；换上限前关闭 Start，重新解锁并确认。
2. 每档先短直线，再缓慢左右移动，记录实际速度、停车距离、直线偏差和缓弯稳定性。
3. 每次恢复先低档起步，持续满足远距离条件才升档；接近目标或转弯变急立即降档。
4. 转向需求超过 30% 不高于中档，超过 60% 或谨慎跟随时只用低档。
5. 普通跟随左右轮均正转，不得出现倒车、单轮停止或原地旋转。

当前固件名义侧速度：14 档约 160 mm/s、18 档约 206 mm/s、21 档 240 mm/s。
这是目标值，不是本轮地面测量结果。起步要求 `heightScale <= 0.80` 和 3 个不同新鲜帧。
距离分档保留原模拟器的 0.03 滞回，例如低档升中/高的边界为 0.72/0.57。
强度仍为 20%–200%，三档基础最大差速 4/5/6，内侧最低 6。同向调档不主动插入 STOP；
身份、距离或安全门拒绝时仍立即停车，不能为追求流畅取消这些停止。

## 6. 先核对旋转方向与测角

保持 Start 关闭、主动搜索关闭：

1. 手动左右原地转向，确认按钮与真实方向一致。
2. 点击独立测角的左转/右转，缓慢转动手机，正向进度应增加，反向进度减少并提示方向错误。
3. 重新把手机固定到车体，确认传感器就绪。数据中断或缺少陀螺仪/重力数据时不要开启搜索。

独立测角按钮不向 BLE 发送运动命令。当前固件纯旋转有最低 80 mm/s 保护，
`c5` 不是 5 mm/s，也不是 5°/s。

## 7. 低档定向搜索

先悬空核对命令，再空旷落地。悬空时车体不转，不能验收真实转角闭环。

1. Start 前开启搜索，设置 `c5 / 90° / 5 秒`，手机固定，旁人准备断电。
2. 建立可信跟随，让目标从左侧或右侧离开。只有可信侧边离屏且没有其他候选才应搜索；居中消失应静止等待。
3. 先显示 `c0,0` 和停车等待，再出现左转 `c-5,5` 或右转 `c5,-5`。
4. 任意高低置信人物出现立即停车验证；错误候选持续可见时，不得反复旋转。
5. 恢复授权后至少停车稳定 300 ms，再从低档起步。
6. 时间或角度耗尽，应静止保留 Start 和记忆，不自动再转一轮。
7. 旋转中传感器失效，或净反向达到 5°，应停车并撤销解锁。排查后才能重新开始。

软件在提交 STOP 后至少等待 300 ms，转角从首次提交旋转命令起算；提交和 GATT 成功都不等于
物理停稳。总时限从接纳离屏事件开始，包含软件等待、固件制动和验证，固件继续负责反馈制动。
首次 c5 通过后才逐档提高旋转速度，每档记录制动距离和搜索过冲，不直接跳到最高档。

## 8. 日志与验收记录

仅打开「记录日志」才生成诊断 CSV/crop；关闭日志不影响内存 Gallery。四区分别查看
Anchor、Adaptive、Recent、Quarantine，重复但可靠的外观可能只进入 Recent。
原有转弯参数记录机制保持不变，不额外保存逐帧图片。

帧 CSV 末尾新增 `real_intent,real_phase,real_gear,real_left,real_right,real_reason`。
它们是本帧上位机决策，不是电机反馈；调度器可能因过期、角度或传感器异常更早停车。
结合 `CartControl`、BLE 写入日志、现场录像和下位机反馈核对真实执行。

| 项目 | 需要记录 | 当前状态 |
|---|---|---|
| 身份 | 黄绿切换、恢复时间、错误目标是否获得非零输出 | 待真车测试 |
| Gallery | 四区数量、来源、拒绝原因、是否混入路人 | 待真车测试 |
| 帧时效 | 完整处理耗时、显示延迟、400 ms 运动门触发 | 待手机测试 |
| 三档跟随 | 实际速度、轨迹、停车距离 | 待真车测试 |
| 搜索 | 方向、制动、净转角、过冲、总时限 | 待真车测试 |
| 异常 | 断连、退后台、急停、传感器中断 | 待真车测试 |

任何错误身份获得非零输出均判失败，不能用 Gallery 增长或总体体验改善抵消。
最终自动化与构建信息见 [上位机开发日志](../dev/OpenBot/android/cartfollow-devlog.md) 第 32 节。
