## 本次优先复测：延后学习与长时返回

仅使用 Human Cart Simulator。本轮不改变真实车速度或跟随策略，不连接底盘执行模拟命令。
绿框可标为“身份已验证”或“连续保持”；是否运动以独立的 `c左,右` 和动作原因判断。

1. Start 前选“动态 Gallery”，确认“近期记忆”默认开启，需要复盘时开启日志。采集确认后
   静止 30 秒，分开记录 Anchor、Adaptive、Recent、Quarantine。Recent 容量 16、从原采集
   时间起有效 5 秒、采样间隔至少 300 ms；重复可靠样本可进入 Recent，Adaptive 不必增长。
2. 让人物缓慢转为侧面、背面，再转回来。短时低分应显示“连续保持”，最多 1 秒低档模拟
   续行；若本来已经停车，则不能靠宽限重新起步。分数较低或超时会显示“停车学习”，
   此时原目标局部连续的弱分候选可积累，但至少 5 个新鲜样本、1.5 秒，以及之后连续 3 个
   独立强端点全部满足才可批准。持续弱分、自相似、缓存和持续绿框不能晋升；转身不保证成功。
3. 测试逐渐蹲下、坐下再起身，以及近距离四边贴合/双侧贴合大框。四边裁切本身均放行，
   仍须满足可见尺寸、宽高比和身份门；侧边持续退出或变窄属于离屏风险，冻结学习。
   尺寸骤变、低置信检测或身份过低时停车仍属预期。不要用快速甩动镜头
   代替人物自身的姿态变化来判定本轮学习效果。
4. 关闭 Start，保持动态 Gallery 但关闭“近期记忆”，重新确认并重复前述动作。开关在
   Start 后应不可操作；另用固定 Gallery 做对照，固定模式所有动态区域均不更新。
5. 安排相似衣着的路人同框、交叉和遮挡，并重复转向路人、转回原目标。此时应冻结候选、
   清空 Recent，不因近期样本相似就让新 track 接管。错误人物的绿框或非零输出分别记录，
   任何错误身份非零输出均判失败，不能以“衣着相似”解释为通过。
6. 原目标离开超过普通等待及 ghost 窗口，再从不同位置返回。到期应 `PARKED_WAIT`、`c0,0`，
   Start 保持开启，Anchor/已接纳 Adaptive 保留；返回进入 `AUTO_VERIFY`，无需强制重拍。
   新轨迹全局验证需同一候选连续 5 次新鲜证据、至少 1200 ms，每次分数 >= 0.85、margin
   >= 0.08、Anchor >= 0.70，间隔 <= 500 ms；授权前不前进、不换锁、不学习。
7. 测试快速左右离屏、双边贴合后单侧收缩，以及搜索结束后继续无人。结束后应静止等待，
   不能自动再旋转；需要先恢复可信跟随，再发生新的离屏事件，才可重新触发搜索。
8. 每轮记录正确目标黄绿切换次数、停车总时长、恢复时长、各 Gallery 分区变化，以及误接管
   次数。分开记录“动作连续性改善”和“错误身份抑制”，不能只用 Gallery 数量判断效果。
9. 在采集或识别过程中关闭 Start、重新启动，并主动重拍一次。旧会话的框和样本不得出现在
   新会话；新采集确认仍按首次流程进行。此项用于检查迟到推理结果，不要求快速反复点击。

新增 frame CSV 列：`identity_state,retain_target,motion_permit,sampling_permit,`
`hold_remaining_ms,continuity_reason,identity_reason,recent_enabled,recent_size,recent_score,recent_reason`。
`motion_permit=1` 仅是身份层许可，最终命令仍可能因距离或安全门为零。
Recent 的相似度是已有样本对当前特征的 top-3 均值，至少 3 个样本才有支持值；当帧新样本
在评分后才加入。日志开启时 `gallery/<序号>_recent_frame_<帧号>.jpg` 对应实际接纳的 upright crop。
日志关闭不影响内存更新，也不保存 Recent 图片。

本轮额外追加 `anchor_count,adaptive_count,quarantine_count,deferred_review,`
`recent_matching_support,recovery_type,recovery_matches,recovery_required`。延后图像文件名
包含原始源帧与批准帧，例如 `deferred_source_123_approved_145`，不能按批准帧重新裁图。

## 持续回归：帧过期与误接管

先只使用模拟器，不连接底盘。上一次日志中确实出现了 T1 换成 T2 后的非零模拟输出。
因此本次不能只检查“有没有框”，必须同时看实际模拟命令和身份复核提示。

1. 打开日志，Start 后采集、确认目标，让目标较近、人物框接近满屏，停留至少 10 秒。
   四边裁切允许存在，但可见宽高比须 >= 0.15。应完成首次倒计时；偶发慢帧时等待新鲜画面，
   Start 不自行关闭，
   确认面板仍能操作；新鲜帧回来恢复框。旧框过期后消失仍是正确行为。
2. 让目标和一位路人同时出现，再把镜头转向该路人。应保持 `c0,0`，不得出现已授权绿框，
   主提示应为身份存疑或复核中。持续观察 10 秒，不能因为路人一直在画面内就自动接管。
   重复几次，尤其测试相似衣着。已知干扰者仍禁止接管；新 track 不能靠 Recent/局部姿态
   样本直接接管，必须从零经过全局验证。新 ID 是否仍被识别为干扰者属于手机待验证风险。
3. 将镜头转回原目标，保持局部连续性。应取得 3 次不同的新鲜 ReID 后恢复；已跟随过的
   目标不重复 3 秒倒计时，旋转后先停车稳定 300 ms。连续性不足或新 track 返回时，应静止
   执行全局 5 次/1200 ms 验证；历史歧义不再永久阻塞，当前多人/关联歧义仍暂停或重置。
   不保证候选一定通过；任何缓存、单次高分或 Recent 支持都不能代替独立证据。
4. 若确实要重新标定，主动关闭 Start 后重新开启，重新采集 15 帧并确认；首次确认页仍可
   重拍。旧 Gallery 与身份排除记录应清空，并再次执行首次倒计时。普通恢复不再弹出强制重拍。
5. 最后复测定向搜索时间上限、Start 关闭和页面退出，确认无新帧也不会无限保留搜索。

日志复盘：`frame_log.csv` 末尾追加 `copy_ms,legacy_match_ms,initialization_ms,decision_ms`；
`events.csv` 的 `frame_presented` 增加 `copy_ms,match_ms,initialization_ms,decision_ms,`
`log_submit_ms,ui_wait_ms,identity_gate,fresh_matches`。日志提交和 UI 等待在对应操作完成后
记录为事件，不把尚未发生的时间写成 0。采集阶段也可在呈现事件中检查耗时。

手机性能验收应比较 `result_age_ms`/`source_age_ms` 的中位数、P95、最大值及过期次数，
区分检测/ReID 与其余处理耗时。近满屏目标是否稳定低于 500 ms 仍以新版手机实测为准。

已完成的首轮记录 `cart_diag_20260903_151115`：191 条采样呈现记录，源帧年龄中位数
68 ms、P95 107 ms、最大 119 ms，超过 500 ms 为 0；用户仍报告最后一次路人变绿且
原目标未恢复。该轮身份验收失败，不能因外观相似而判通过。Gallery 未增长的原因包含
身份不足、多人冻结、连续性不足和样本重复，不能统一解释为图像质量问题。

## 2. 帧一致性与 FPS

1. 打开日志，启动并确认目标，让人物缓慢横移，观察框、确认照片与 crop 的方向及位置。
   应能以 generation / seq 关联同一获准推理帧的 Detector、ReID 和实际采样图像。
2. 在推理期间关闭 Start，再重新启动；补测退后台后返回。旧 generation 结果不得覆盖新
   会话目标、框或 Gallery。帧图像不得在等待 ReID 时被后续相机帧改写。
3. 加入第二人并改变位置，检查缓存证据的源 track、seq 和年龄。缓存可以复用有效证据，
   但不得转借另一 track，也不得把同一 ReID 完成结果重复计入新鲜 3/5 次确认。
4. 对照日志中的完成次数和实际窗口检查 FPS，分别记录 Detector、ReID 和完整管线耗时。
   停止或无新结果后不能把旧显示值当作持续完成帧率。旧 FPS 只是 Detector 耗时换算，
   不是相机帧率、端到端吞吐或手机流畅度的充分证据。

## 3. 正常安装与 Gallery 学习

1. 选择动态 Gallery，确认单个目标，保持手机和人物静止。只要 locked track、身份、
   图像质量及其他门控满足，即使输出为零也应允许采样；固定 Gallery 用作不增长对照。
2. 在 0/90/180/270 度画面方向分别测试上下左右截断、双侧贴合和近满屏大框。upright 可见高度占转正后
   画面高度的比例，普通 Gallery 至少 18%，Quarantine 至少 12%，不是面积比例；
   bbox 与画面交集至少 32 x 64 像素，可见宽/高至少 0.15。
   四边截断本身不得独立拒绝或称作模糊/坏图；过小、过窄与持续侧向退出分开记录。
   通过几何门不等于必须入库，侧向退出中的学习仍冻结。
3. 逐步后退或缩小可见区域，观察高度比例不足和 crop 尺寸不足的几何拒绝，并与身份拒绝
   区分。当前没有实现模糊或曝光检测，本指南不评估模糊分类能力，也不把质量拒绝解释为
   检测出了模糊。精确阈值边界由自动化覆盖，手持测试不声称精确到像素。
4. 已验证原目标在单人、高置信实测和可靠局部关联下转身，原始分数 [0.60,0.85) 可开启
   Quarantine 延后片段；最多 16 特征、整段 5 秒、源采样间隔 >= 300 ms，相邻特征 cosine
   >= 0.85。至少 5 个新鲜样本、源跨度 >= 1.5 秒后，还必须有连续 3 个独立新鲜强端点：
   冻结分数 >= 0.85、Anchor >= 0.70、margin >= 0.08。仅停留、自相似或缓存不批准。
5. 复核只用开启时冻结的 Anchor + 全局合格 Adaptive，不用 Recent、本段候选或后来新增
   样本。批准样本保留原源帧、原时间和版本；本帧不能因接纳而获得身份许可，最早下一帧
   才参与匹配。Recent 不重新计寿命；延后 Adaptive 只支持原轨迹局部姿态，不进入全局分数。
6. 在隔离学习中加入干扰者、遮挡或切换 track，检查冻结/清理及原因。错误人物不得被吸收；
   冻结后需重新得到可信原目标，不能用弱分马上重启候选。非 ReID 帧不会仅因没有新特征
   清空片段。绿框出现而无新样本可能是门控、重复视角或时序未满足，不直接判为采样故障。

## 4. 左右离屏与定向重捕

1. 确认并进入过跟随，让单个可信目标缓慢向屏幕左边移动，再完全离屏。触发依据应来自
   最近 800 ms 实测框，最后强身份年龄 <= 1 秒，框进入左侧 15% 区域、至少 2 次位置观测，
   累计向外位移 >= 屏幕宽度 2%。连续保持不刷新强身份时间，距离 UNKNOWN 不应抹掉历史。
2. 连续缺失至少 2 帧且达到 100 ms 后，才允许定向搜索；先取消线速度，搜索只显示原地
   左转模拟命令。对右侧对称重复，方向按手机屏幕判断，不按相机原始缓冲区判断。
3. 让任意人物在搜索中出现。应先停车核验，不能见到人就继续转或前进。目标恢复需要新鲜
   身份证据；错误人物不能凭 Quarantine 分数进入跟随。
   `DIRECTED_REACQUIRE` 恢复最多评估 5 个高低置信候选，只有高置信者可获授权。
   超预算应停车，不能声称已排除其余候选。全局不使用 Recent 或延后局部样本授权。
4. 重复双侧贴合后单侧变窄、左右镜像、仅 2 至 3 次位置更新、一次 < 1% 中性抖动。
   对照居中消失、明显反向、多人歧义、方向不足、800 ms 历史过期、最后强身份超过 1 秒
   和仅上下截断，避免误判离屏。若低分检测仍续接目标，不应提前算失联；有其他未排除
   人物时保持静止验证，不能把“目标没续接”当作“画面完全无人”启动旋转。
5. 分别选 1 秒和 10 秒定向窗口，穿插旋转、有人出现、停车验证、候选再次消失。
   总计时覆盖所有阶段，不因阶段切换或新候选重置；达到时间或角度上限后应 PARKED_WAIT，
   `c0,0`、Start 保留、可信 Gallery 保留，静止等候，不强制重拍、不自动再旋转。
6. 分别选普通重捕 2 秒和 5 秒，测试非定向的普通无人场景。该规则应独立工作，不能抢占
   已启动定向搜索的超时所有权，也不能替定向搜索无限续期；普通等待到期同样进入
   PARKED_WAIT。记录触发者、owner、开始时间、
   阶段变化与结束原因，以区分两个计时器。
   普通无人计时应从首次缺失开始，即使状态暂时仍为 `FOLLOW`。补测低置信的可能人物
   仍在场：应保持普通等待，不按完全无人结束；不要将状态转换时刻误当成首次缺失时刻。
7. 比较逐帧处理与没有新帧时的定时轮询：普通超时/角度结束都应保留会话并停止搜索。
   继续无人不能反复触发；须先恢复可信 FOLLOW，再形成新离屏事件才能再次旋转。
8. 补测 Start 关闭、退出页面及可触发的硬安全异常，确认立即停止并结束会话，不残留命令。
   PARKED_WAIT 不延长旧帧有效期，不为超时/无效证据提供运动许可。

## 5. 独立陀螺仪测试

1. Start 保持关闭，不采集、不确认目标，启动独立左转测试并缓慢左转手机，应有有效转角。
2. 停止，再测试右转，检查方向对称。测试中做一段反向旋转，净转角应抵消而不是只增不减。
3. 按停止后角度不再作为进行中的测试进度累计；按重置后应回到零并清除上一轮状态。
4. 检查陀螺仪和重力数据年龄均不超过 500 ms；传感器缺失或任一路数据陈旧时应显示不可测/无效，而不是保留
   有效测量假象。无法人工制造的陈旧边界记录“待自动化覆盖”，不能写成手机通过。
5. 回到定向搜索检查角度与时间的结束原因。净转角不是底盘真实转角，独立测试不应打开
   Start、确认身份或发送 BLE。无有效角度时仍须有搜索总时间兜底。

## 6. 距离与取证

1. 在其他条件尽量相同时改变人物远近，记录距离状态和相对图像量。新增距离诊断不改变
   原跟随/调档阈值，现有模拟器仍使用距离参与调档；新增诊断不能当作米制测量。
2. 失败时保留日志中的版本、generation、seq、track、结果年龄、完成计数、分阶段耗时、
   belief、Anchor/Adaptive/Recent/Quarantine 分区、新鲜样本及端点次数、可见高度比例/尺寸/宽高比、
   采样或拒绝原因及搜索计时信息。补充恢复类型/进度、离屏未触发原因和错误身份输出。
   使用下方实际追加字段关联来源和拒绝原因，不将几何门控解释为模糊/曝光检测。
3. 图片和 crop 仅在日志开启时保存。核对实际采样源帧与隔离/晋升事件的关联，不能用晋升
   时画面冒充原样本，也不能把所有绿框帧都视为采样。没有采样事件时没有 crop 不必然是故障。
4. `CartFollowDiagnosticSession` 使用 `Environment.DIRECTORY_PICTURES`，诊断根目录为
   `Android/data/org.openbot/files/Pictures/cartfollow_diagnostics/`。按场景时间找对应
   session 日志，不要求另外拍摄或附加图片。
5. 按“预期 / 实际 / 拒绝或结束原因 / 关联帧与事件 / 是否复现”反馈。私人图片及其衍生
   crop 只用于本地授权复盘，不提交或公开上传；本指南无需图片附件。

已有取证字段（保留顺序；本轮追加字段以最终 CSV 表头为准）：

- `frame_log`：`frame_received_ms`、`sensor_timestamp_ns`、`detector_ms`、`reid_ms`、
  `pipeline_ms`、`result_age_ms`、`dropped_frames`、`observation_source`、`observation_track_id`、
  `screen_left`、`screen_top`、`screen_right`、`screen_bottom`、`distance_diagnostic`。
- `identity_log`：`reid_observation_id`、`reid_observation_ms`、`reid_source_frame`、
  `reid_scored_track`、`reid_fresh`、`crop_visible_width_px`、`crop_visible_height_px`、
  `crop_height_ratio`、`crop_normal_reason`、`crop_quarantine_reason`。
- `events` 中的 `frame_presented`：`source_age_ms` 与 `generation`。

用 `reid_observation_id` 和 `reid_fresh` 检查新鲜证据是否被重复计数，用 `reid_source_frame`
与 `reid_scored_track` 核对源帧和轨迹；用 `crop_height_ratio`、可见宽高及两类 reason 区分
普通/隔离采样的几何拒绝，再结合身份日志判断身份门控。`frame_presented` 的源年龄与会话
generation 用于检查呈现结果是否过期或跨会话，不只看 Detector 耗时。

延后学习还须核对源帧与批准帧、session、gallery revision、原始采集时间、独立端点分数
及 margin；日志开启时检查 crop 像素/方向/尺寸对应源帧而非批准帧，关闭时内存学习仍可继续。

本轮验收状态分别记录：最终自动化结果待补录、APK/安装标识待补录、手机场景待验证。
每项取得对应证据再更新，不能把历史通过、构建成功或单个手机案例当作完整验收。
