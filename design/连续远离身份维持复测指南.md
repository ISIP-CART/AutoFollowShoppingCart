# 连续跟踪与手机离线日志复测指南

适用：Human Cart Simulator 和真实小车跟随；策略版本 `continuity-v2`。
本指南替代此前“外观两次低分就停车”“连续目标只限低档”的复测口径。当前 APK 与自动化结果见
[开发日志第 35 节](../dev/OpenBot/android/cartfollow-devlog.md)。手机实测尚未完成。

## 1. 先确认当前行为

| 场景 | 预期身份/跟踪行为 | 运动和学习 |
|---|---|---|
| 单人连续远离、侧身、外观分低 | 连续跟踪，不因 ReID 低分变黄 | 距离有效时 c14/c18/c21 |
| 低置信但原目标唯一续接 | 检测偏弱 | 最高 c18，不学习 |
| 路人经过、原目标关联清晰 | 多人核验，保持原目标 | 继续跟随，冻结学习 |
| 两个候选争抢原轨迹或两次身份冲突 | 重捕验证 | 取消前进，不直接换人 |
| 短漏检 | 立即停止前进 | 500 ms 内唯一返回，三帧稳定恢复 |
| 长丢失后返回 | 全局重捕验证 | 五次新鲜证据、至少 1.2 秒后恢复 |
| 距离合适、过近或 UNKNOWN | 显示距离原因 | 停车；不以框色判断是否该前进 |
| 急停、断连、源帧过期、旧会话 | 安全停车 | 不因身份连续而绕过 |

新姿态可以凭可靠单人连续片段进入全局 Adaptive，不需要回到初始化姿态。相邻特征不连续只重启
学习片段，不应阻断可靠位置跟踪。绿框不等同强身份认证。

## 2. 不连电脑记录与导出

1. 打开跟随页面，先打开“记录日志”，看到“日志记录中”后开始采集和确认。默认关闭时不会建立新记录。
2. 完成测试，先关闭 Start，让车辆停车。页面显示记录收尾；图片积压只影响图片，不应阻塞车辆控制。
3. 点击“测试记录”，找到对应日期、模式的记录。若还在收尾，稍后点“刷新记录”。
4. 选择“保存 ZIP 到手机文件夹”，在系统文件选择器选择“下载”等位置；或选择“系统分享 ZIP”。无需 adb。
5. 导出完成后检查 ZIP 能打开；取消或失败不会删除原记录。异常退出的“不完整”记录也可导出。
6. 若出现“日志写入异常”或丢弃计数增长，拍下错误信息并保留可导出的部分，不把缺失图片当作目标未出现。

原目录：`Android/data/org.openbot/files/Pictures/cartfollow_diagnostics/`。手机文件管理器若不能直接打开
Android/data，可使用应用内导出。没有自动上传、录像或自动删除旧记录。

## 3. 测试顺序

先模拟器，再真实车悬空，最后空旷低速落地。真实车首次主动把最高档设为 14，关闭可选主动搜索；
通过停车和通信检查后，再分别验证 18、21 档。准备能够立即物理断电的同学。

- **静止与远离返回**：确认并完成首次倒计时；静止 10 秒、缓慢远离 15 秒、返回，重复三次。目标始终可见时
  记录黄色占比、停车次数、最长恢复时间和实际档位。距离合适应停车，不能为了绿框而继续前进。
- **侧身与转身**：持续变姿态，分别记录 ReID 分数、跟踪状态和学习原因。极端宽高变化可能使距离 UNKNOWN，
  应按距离停车单列，不能归为身份低分停车。
- **短漏检**：短暂遮挡后立即返回。漏检当帧取消前进，500 ms 内唯一续接后第三个稳定实测帧恢复；不重复倒计时。
- **新姿态全局记忆**：在新姿态连续跟随数秒，确认出现 `deferred_approved`，随后离开至少 3 秒，再保持新姿态返回。
  检查全局 Adaptive 参与匹配，五次新鲜证据、至少 1.2 秒后确实重新出现非零轮速。
- **路人经过**：让路人从旁侧经过，原目标不交叉。应保持原目标，停止学习；再做交叉/遮挡换人，出现关联竞争时停车。
  对另一候选两次显著更高分的身份冲突，要求先停车核验，不直接切换。
- **硬安全**：测试 Start 关闭、页面退出、断开 BLE、急停。检查真实轮子停车；自动测试无法代替固件与物理制动验证。

单独记录误跟、路人样本入库或错误身份的非零输出，不以总体更顺畅抵消这些事件。

## 4. ZIP 中检查什么

| 文件/目录 | 检查内容 |
|---|---|
| session_info.json | 模式、构建标识、日志版本、检测/关联/恢复/采样参数 |
| frame_log.csv | 旧列保留；追加 tracking_session/frame/ms/tier/stable/max_gear/reason；实际轮速与首要限制原因 |
| identity_log.csv | ReID 源帧、observation ID、原始时间、fresh、Anchor/Adaptive 与采样原因 |
| candidate_log.csv | 每个高/低置信框的 bbox、轨迹绑定、身份候选资格、关联分数与竞争状态；`raw_low` 不应计入多人 |
| control_log.csv | 控制提交、配对分数、队列替换、GATT 写入结果、连接和急停；按队列 generation 对照源帧 |
| gallery_provenance.jsonl | 样本来源、批准帧、全局资格与批准依据 |
| crops/、gallery/、overlays/ | 限频的目标样本与关键场景，缺图时核对丢弃数/写入错误 |
| summary.json、status.json | 完成状态、时长、计数、丢弃和错误；缺失摘要意味着记录可能被中断 |

`gatt_success` 是蓝牙写入成功，不是电机执行反馈。缓存 ReID 的 observation ID 和来源时间必须保持不变；
新检测时间可以前进，两者不能混用。批准样本最早从下一帧开始参与匹配。

测试记录含现场照片，保留在手机或本地；需要分享时由测试人员在系统分享页自行选择接收方，不提交私人图片到仓库。

## 5. 明日现场复测补充（2026-09-04）

当前观察仅表明连续可见的跟随目标有所改善。拐角转弯和“人物从车前走到车后后小车自转”
尚未解决，也不在本轮 APK 的通过范围内。普通跟随只做前进差速缓弯；原地旋转只可能来自满足
严格条件的定向搜索，不能把它当作身后跟随。

明日每段测试都打开日志，并在停止、收尾完成后导出 ZIP：

1. 直线远离/返回、侧身转身，确认连续性改善没有掩盖距离或安全停车。
2. 缓慢 90° 拐弯与货架拐角离屏，记录离屏方向、是否停车、是否进入搜索和车轮实际方向。
3. 人从车前绕到车后，记录系统是否按设计停车；不把未经过确认的自转当成预期动作。
4. 路人交叉、急停、断连各做一次，保留录像或人工记录与 ZIP 对照。

优先检查 `frame_log.csv` 的 tracking 和限制原因、`identity_log.csv` 的 ReID 来源、
`candidate_log.csv` 的原始低置信框与有效候选数、`control_log.csv` 的请求/队列/GATT 事件及
`summary.json` 的写入错误和丢弃数。静止单人测试中即使 `raw_low` 持续出现，
`identity_candidate_count` 也应保持 1，不得出现 `multi_check_timeout`。GATT 成功不代表
轮子已执行；现场结果将用于判断下一步是补视觉方向假设、转向控制映射，还是底盘执行与安全门标定。
