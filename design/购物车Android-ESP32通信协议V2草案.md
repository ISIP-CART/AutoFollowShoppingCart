# 购物车 Android—ESP32 通信协议 V2 草案

版本：`V2-DRAFT-0.1`
状态：等待下位机同学确认，尚未冻结，尚未在 Android 或 ESP32 中实施。

## 1. 目的与兼容边界

V2 为三轴麦轮运动、三路近场传感器和运动接受回执预留统一接口。当前自动跟随仍使用既有左右轮命令，且始终不使用侧移。本草案确认前不得开发 `m`、`d`、`g`、`a` 命令，也不得在遥控界面增加侧移按钮。

协议继续使用 ASCII 文本和换行符结尾。单行最长 128 字节（含换行）；BLE 接收端必须保存半包并循环提取粘连的多行。链路层已有校验，本版不增加应用层 CRC。未知、缺字段、越界或过长命令必须拒绝，不能按部分字段执行。

## 2. V1 命令完整保留

| 报文 | 含义 |
|---|---|
| `f` | 查询固件能力 |
| `h<ms>` | 心跳／看门狗周期相关的既有命令，语义保持现状 |
| `c<left>,<right>` | 既有差速运动命令 |
| `c0,0` | 普通停车，任何运动方言下均有效 |
| `!S,<seq>` | 急停，任何状态和运动方言下均有效 |

V2 固件建议对 `f` 回复：

```text
fCART_AT8236:p2:m3:r3:ack:s:
```

其中必须保留 `CART_AT8236`，使旧 Android 仍可识别设备。其余能力段的最终定义由上下位机联调时冻结。

## 3. 连接内运动方言

每个 BLE 连接周期中，第一条非零 `c` 或 `m` 命令锁定运动方言。锁定后，另一方言的非零命令返回拒绝，直到断开重连。`c0,0`、三轴全零命令和 `!S` 始终有效。这样可以避免上下位机在同一运动周期用两种速度单位反复覆盖。

### 3.1 三轴运动命令

```text
m<seq>,<vx_mmps>,<vy_mmps>,<omega_mradps>
```

- `+vx`：向前；`-vx`：向后。
- `+vy`：向左侧移；`-vy`：向右侧移。
- `+omega`：从车顶向下观察逆时针左转。
- `vx`、`vy` 范围均为 `-240～240 mm/s`。
- `omega` 范围为 `-1000～1000 mrad/s`。
- `seq` 为 Android 在当前连接内递增的无符号序号；回绕规则由下位机确认。
- ESP32 负责麦轮逆运动学、M1—M4 轮序、单轮方向修正、整体归一化和四轮限速。
- 自动跟随固定发送 `vy=0`；侧移仅为后续手动遥控测试预留。

### 3.2 接受回执

```text
a<seq>,m,<OK|REJECT>,<effective_vx>,<effective_vy>,<effective_omega>,<state_or_reason>
```

回执表示 ESP32 已接受或拒绝目标，并回报限幅后的目标值；它不表示电机、编码器或底盘已经执行。拒绝时有效速度全部填 `0`，原因使用稳定、可记录的短字符串，例如 `DIALECT_LOCKED`、`RANGE`、`LOCAL_STOP`、`SENSOR_STALE`、`DRIVER_FAULT`。

## 4. 传感器快照

线上的实际报文不得换行，格式为：

```text
d<seq>,<emit_ms>,<left_mm>,<left_status>,<left_age_ms>,<center_mm>,<center_status>,<center_age_ms>,<right_mm>,<right_status>,<right_age_ms>,<risk_mask>
```

状态码：

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | `VALID` | 当前测距有效 |
| 1 | `RANGE_INVALID` | 超出有效量程 |
| 2 | `SIGNAL_INVALID` | 回波或信号质量不足 |
| 3 | `STALE` | 样本过期 |
| 4 | `BUS_ERROR` | 总线／采集错误 |
| 5 | `NOT_PRESENT` | 本机未安装该传感器 |

无距离样本时距离字段为 `-1`。Android 只有在状态为 `VALID` 且 `age_ms <= 200` 时才能使用距离；不得把 `-1` 当成远处无障碍。

`risk_mask` 位定义草案：

| 位 | 掩码 | 含义 |
|---:|---:|---|
| 0 | `0x01` | 左前角阻挡 |
| 1 | `0x02` | 中央低于会话舒适距离 |
| 2 | `0x04` | 右前角阻挡 |
| 3 | `0x08` | ESP32 本地硬停车 |
| 4 | `0x10` | 必要传感器过期停车 |
| 5 | `0x20` | 驱动故障 |

高位保留并置零。中央“舒适距离阻挡”用于禁止向前，不应单独禁止原地对准；本地硬停车和左右角禁行可以覆盖上位机目标。

## 5. Android 会话配置

```text
g<seq>,<comfort_distance_mm>,<telemetry_period_ms>
```

- `comfort_distance_mm` 限幅为 `600～1200 mm`，默认 `800 mm`，步长由 Android 界面限定为 `50 mm`。
- `telemetry_period_ms` 限幅为 `50～500 ms`，默认 `100 ms`。
- Android 持久化用户设置并在连接建立后下发。
- ESP32 只保存本连接的配置，断电或断连后恢复默认值，并用 `a` 类配置回执回显实际生效值。配置回执的方言字段建议使用 `g`，最终格式待确认。

旧协议连接中 Android 不显示传感器控制项，避免用户误以为设置已经生效。

## 6. ESP32 本地安全提案

1. 中央超声波不超过 `300 mm` 时硬停车；超过 `400 mm` 且连续 3 帧有效后解除风险。
2. 左／右红外不超过 `200 mm` 时，分别禁止向对应侧原地转向和侧移；超过 `300 mm` 且连续 3 帧有效后解除。
3. 关键传感器超过 `200 ms` 没有有效更新时标记过期；运动中必要传感器全部不可用时停车。
4. 风险解除后必须收到新的运动命令，旧命令不得自动恢复。
5. `!S`、通信看门狗和驱动故障的优先级高于所有运动命令。
6. 当前没有后侧传感器覆盖。协议、日志和界面不得声称后退或原地旋转具有完整后向防撞能力。

## 7. 完整报文示例

### 7.1 正常连接、配置和前进

```text
Android -> ESP32: f
ESP32  -> Android: fCART_AT8236:p2:m3:r3:ack:s:
Android -> ESP32: g1,800,100
ESP32  -> Android: a1,g,OK,800,100,0,CONFIG_APPLIED
Android -> ESP32: m2,160,0,0
ESP32  -> Android: a2,m,OK,160,0,0,ACCEPTED
ESP32  -> Android: d20,15340,640,0,22,1350,0,18,610,0,25,0
```

### 7.2 越界拒绝

```text
Android -> ESP32: m3,400,0,0
ESP32  -> Android: a3,m,REJECT,0,0,0,RANGE
```

### 7.3 方言冲突

```text
Android -> ESP32: c14,14
Android -> ESP32: m4,100,0,0
ESP32  -> Android: a4,m,REJECT,0,0,0,DIALECT_LOCKED
```

### 7.4 普通停车与急停

```text
Android -> ESP32: m5,0,0,0
ESP32  -> Android: a5,m,OK,0,0,0,STOPPED
Android -> ESP32: c0,0
Android -> ESP32: !S,6
ESP32  -> Android: a6,m,OK,0,0,0,EMERGENCY_STOP
```

急停回执中的方言字段是否固定为 `m`，或改用 `s`，需由下位机确认；无论是否成功回传，ESP32 都应先本地执行急停。

### 7.5 中央过近与传感器失效

```text
ESP32  -> Android: d21,15440,620,0,20,280,0,15,600,0,24,10
Android -> ESP32: m7,120,0,0
ESP32  -> Android: a7,m,REJECT,0,0,0,LOCAL_STOP
ESP32  -> Android: d22,15540,-1,3,230,-1,3,235,-1,3,228,24
```

第二条快照表示三路均过期，并置位本地硬停车与传感器过期停车。

### 7.6 回执超时

```text
Android -> ESP32: m8,100,0,120
# Android 在约定期限内未收到 a8：停止刷新非零目标并发送零命令
Android -> ESP32: m9,0,0,0
```

具体回执超时阈值需结合 BLE Notify 带宽和固件调度测量后冻结。

### 7.7 手动左右侧移

```text
Android -> ESP32: m10,0,100,0
ESP32  -> Android: a10,m,OK,0,100,0,ACCEPTED
Android -> ESP32: m11,0,-100,0
ESP32  -> Android: a11,m,OK,0,-100,0,ACCEPTED
```

上述报文仅定义未来手动测试语义，不代表当前 Android 已提供按钮。
